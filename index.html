01 Overview

Editable Code World to Long-Horizon Video with Instance-Level Memory

MemOIR converts a driving video into an editable code world with a closed-loop agent that is training-free and built on off-the-shelf models, and generates photorealistic video from it. An instance-level KV memory caches each object's tokens and re-embeds them where its block reappears, preserving instance identity over long horizons.

  1. 02 · Video → Code World Reconstruct A training-free LLM agent with off-the-shelf perception models reconstructs a driving video as a 4D blocks world and exports it as an editable Python program.
  2. 03 · Controllable Generation Edit Agent behavior is edited in code: speed profiles, stops, timing, lane changes, and inserted or removed vehicles.
  3. 04 · Long-Horizon Generation Render A video model conditioned on the blocks world, with instance-level memory, generates long, identity-consistent driving video.

Instance-level KV Memory Based Long-Horizon Generation

Long rollouts in which each vehicle keeps its appearance when it leaves the view and returns.

(a) Cache

Per-instance KV storage

Keys and values are stored from each instance's most visible observations, together with box-local 3D coordinates.

(b) Re-embed

Re-embedding on return

When the instance reappears, its cached keys are re-embedded with rotary position where its block projects in the new frame.

(c) Attend

Instance-aware attention

An instance-aware attention mask lets each query read only the memory of the instance that owns it.

45.6%re-identification of returning vehicles, compared with at most 11.0% for prior methods

02 Video → Code World

Video to Code World via a Closed-Loop Agentic Pipeline

A training-free, closed-loop LLM agent operates in a stateful Python kernel: it calls off-the-shelf perception models, inspects the intermediate results, and revises the world until it agrees with the video, without ground-truth labels or poses. We call this 3D understanding and reconstruction harness SceneClaw.

(a) Perception tools

Called by the agent on demand

Each tool is a function in the agent's Python kernel; the agent decides when to call it and inspects the result.

  • Depth Anything 3 (multi-view): metric depth and camera poses estimated from the video
  • Mask2Former panoptic segmentation and Mapillary Vistas lane markings
  • SAM3 text-prompted tracking of vehicles, people, traffic lights, signs, poles, buildings and walls
  • WildDet3D 3D vehicle detection, with depth within 3–6% of ground truth out to 70 m
  • RTMPose pedestrian skeletons aligned to their boxes

(b) Verification tools

Called after every edit

  • Rendering tools project the current world onto the image and into a bird's-eye view at several scales, including far-range sky and road views; the agent compares the result with the video and corrects any discrepancies.
  • A final overlay check on the first, a middle, and the last frame concludes the loop.

(c) Output

Editable Python scene file

  • Static world: one aligned slab per building with street-side facade strips, walls, vegetation crowns, lane and road lines, poles, signs, and traffic lights with symbolic content.
  • Agents, each with a persistent ID, a fixed size, and a trajectory, plus per-frame traffic-light states.
  • Saved as scene_world.py and rendered by a single shared renderer; the export–render round trip is accurate to within 10 cm, 7°, and 0.6% of pixels.

Reconstructions

The input video, the reconstructed blocks world, and bird's-eye views at near and far range.

LLM-Agent Refinement from a Single Image

From a single image, an LLM agent refines an automatically built blocks world with off-the-shelf tools and extends it beyond the field of view of the image.

MemOIR generates a drive through the refined world, conditioned on the input image.

03 Controllable Generation

Controllable Video Generation by Editing the Code World

Each agent is represented as a route with a timing table, and a chainable scenario API modifies when and how it moves. Static elements (buildings, vegetation, road lines, traffic lights) are stored as lists. The edited world is rendered by the same renderer into the blocks-world condition, so each edit yields a controlled change in the generated video.

scene_world.py · illustrative edit 
# every agent: a route (xyz polyline) and timing {frame: metres along the route}
car = scene.car("veh017", kind, size, route=[...], timing={...})

car.set_speed(8.0, from_t=40)                  # slow down from frame 40
car.stop(at_t=60, decel=3.0)                  # brake to a stop
car.delay(15)                                 # arrive 15 frames later
car.lane_change(3.5, t0=50, t1=80)            # move one lane to the left
car.place(t, x, y); car.reroute([...]); car.span(t0, t1)

scene.clone("veh017", "veh900").delay(30)      # add a follower
scene.remove("ped045")                         # clear a pedestrian

04 Long-Horizon Generation

Long-Horizon Video Generation with Instance-Level KV Memory

A ControlNet-style branch on a frozen Cosmos-Predict2.5-2B generates video from the blocks world chunk by chunk, with each chunk conditioned on the last frame of the previous one. An instance-level KV bank preserves the appearance of each vehicle across chunks, including after it leaves the view.

Long-Horizon Instance Consistency

A target vehicle (green box) leaves the view and returns with the same appearance.

Long-Horizon Driving Video Generation with Instance Consistency

Minute-long generations. In the U-turn scenes the ego vehicle turns around and drives back along the same street, so buildings and parked cars are seen again from the other side; the straight scenes continue for about a minute. All methods start from the same real first frame.

Forward–Reverse Revisit Consistency

The second half of each video replays the drive in reverse, so every object is seen again. Where outlined, revisited objects are shown in blue on the way out and in orange on the way back.

Pedestrian Identity on Another Video Model

The same instance memory on another video model: a person leaves the view and returns in the next generation chunk with the same appearance (outlined in blue before and orange after).

Face Identity after a Turn-Away

A face turns away at the chunk boundary and turns back with the same identity.

Ablation: Instance-level KV Caching

The memory components added one at a time. The target vehicle (green box) must keep its appearance across generation chunks, or after leaving the view and returning.
