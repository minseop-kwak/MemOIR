01 Overview

Driving scenes as code, rendered back to real video.

Video generative models promise driving simulators that can render arbitrary traffic scenarios, but this requires both precise control over the scene and consistency across long rollouts. Existing driving generators condition only on traffic participants and road layout, leaving the static world, and with it the ego motion, underspecified, while frame-level memories grow quickly and cannot tell which cached tokens belong to which instance. We present MemOIR, a driving video diffusion model conditioned on a view-space blocks-world representation that renders every dynamic and static instance as a 3D block encoding its class, identity, and occlusion, curated automatically from raw driving videos. This representation densely specifies both agent motion and the ego trajectory, and enables object-level KV caching: each instance's tokens are cached from its most complete observations and re-embedded where its block projects when it reappears, attending to far fewer tokens than frame-level caching. MemOIR achieves the most accurate instance placement and ego-motion control among driving generators with competitive visual quality, faithfully places vehicles performing unseen maneuvers such as spin-outs, and substantially improves the identity consistency of returning vehicles.

  1. Part 1 · Real → Sim Reconstruct An LLM agent with off-the-shelf perception rebuilds a dashcam video as a 4D blocks world and exports it as one Python file.
  2. Part 2 · Manipulate Edit Change what every agent does in code: speed, stops, delays, lane changes, new or removed vehicles.
  3. Part 3 · Sim → Real Render A blocks-world-conditioned video model with instance-level memory renders long, identity-consistent driving video.

02 Real → Sim

From dashcam video to a code blocks world.

SceneClaw is a closed-loop LLM agent working in a stateful Python kernel. It uses only off-the-shelf models and code: nothing trained by us, and no ground-truth labels or poses at inference.

(a) Perceive

Off-the-shelf tools

  • Depth Anything 3 (multi-view): metric depth and camera poses estimated from the video
  • Mask2Former panoptic segmentation and Mapillary Vistas lane markings
  • SAM3 text-prompted tracking of vehicles, people, traffic lights, signs, poles, buildings and walls
  • WildDet3D 3D vehicle detection, with depth within 3–6% of ground truth out to 70 m
  • RTMPose pedestrian skeletons aligned to their boxes

(b) Check

Look, compare, repair

  • The agent compares its world against image overlays and a bird's-eye view at several scales, including far-range sky and road checks, and repairs what does not match.
  • A final overlay check on the first, an intermediate and the last frame closes the loop.

(c) Output

One editable program

  • Static world: one aligned slab per building with street-side facade strips, walls, vegetation crowns, lane and road lines, poles, signs, and traffic lights with symbolic content.
  • Agents with one id, one size and a trajectory each, plus per-frame traffic-light states.
  • Saved as scene_world.py and drawn by one universal renderer; the round trip stays within 10 cm / 7° and 0.6% of pixels.

Reconstructions

Input camera, reconstructed blocks world, and bird's-eye views at near and far range, on Waymo Open and Argoverse 2 clips.

03 Manipulate

Every scenario is a few lines of code.

Each agent is a route with a timing table, and a chainable scenario API changes when and how it moves. Buildings, trees, lines and traffic lights are plain lists. The edited world renders through the same renderer and becomes the condition for Part 3.

scene_world.py · illustrative edit 
# every agent: a route (xyz polyline) and timing {frame: metres along the route}
car = scene.car("veh017", kind, size, route=[...], timing={...})

car.set_speed(8.0, from_t=40)                  # slow down from frame 40
car.stop(at_t=60, decel=3.0)                  # brake to a stop
car.delay(15)                                 # arrive 15 frames later
car.lane_change(3.5, t0=50, t1=80)            # move one lane to the left
car.place(t, x, y); car.reroute([...]); car.span(t0, t1)

scene.clone("veh017", "veh900").delay(30)      # add a follower
scene.remove("ped045")                         # clear a pedestrian

04 Sim → Real

Back to real video, with object-level memory.

A ControlNet-style branch on a frozen Cosmos-Predict2.5-2B renders the blocks world chunk by chunk, each chunk re-anchored on the previous one's last frame. An instance-level KV bank keeps every vehicle consistent across chunks and after it leaves the view.

(a) Cache

Per instance

Keys and values are stored from each instance's most visible observations, together with box-local 3D coordinates.

(b) Re-embed

On return

When the instance reappears, its cached keys are re-embedded with rotary position where its block projects in the new frame.

(c) Attend

Only to its own

An instance-aware attention mask lets each query read only the memory of the instance that owns it.

45.6%re-identification of returning vehicles, up from at most 11.0%
98.1%of frames with the spin-out vehicle placed correctly
~24×fewer memory tokens than frame-level caching
40%higher ego trajectory error without static instances

Minute-Long Generation

55-second generations on held-out nuPlan test scenes. After about 20 s of real driving, the ego vehicle makes a U-turn and drives back along the same street in the opposite lane, so the buildings and parked cars passed on the way out are seen again from the other side. Every method starts from the same initial frame; MAGI-1 receives the same text caption and Epona the same ego trajectory.

Ablation: Instance-level KV Caching

Held-out Argoverse 2 and nuPlan clips generated as the memory components are added one at a time. The target vehicle (green box) must keep its appearance across generation chunks (Scene 1) or after leaving the view and returning (Scene 2).

Ablation: Stationary Instances

nuScenes validation scenes generated with and without stationary instances (buildings and vegetation) in the blocks-world condition. For this ablation, both models are trained from scratch for only 1,000 iterations, so the overall video quality is subpar; still, the two settings differ clearly in the speed and movement of the camera.
