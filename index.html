01 Overview

Editable Code World to Long-Horizon Video with Instance-Level Memory

  1. TL;DR: Almost every object in a driving scene can be abstracted as a 3D block. MemOIR is conditioned on this rendered “blocks-world” for generation.
  2. Blocks-world is also a code world, easily built, easily controlled. A closed-loop LLM agent with off-the-shelf tools can convert any videos or images into this representation, no GT needed.
  3. For long-horizon generation, object-level KV caching greatly reduces the memory footprint while ensuring long-term consistency of each instance. Great news: it's a general methodology that works across various backbones and domains beyond driving.

Instance-level KV Memory Based Long-Horizon Generation

Question: What happens after a U-turn? Comparative models (e.g. OmniDreams) forget and completely re-generate the path it just came through, but MemOIR retains the structure and appearance of previous chunks' frames due to efficient instance-level KV memory.

02 Blocks-World Generation

Video Generation Conditioned on a Rendered Blocks World

MemOIR generates driving video from a rendered blocks world. The blocks fix where every object is and how it moves, and this grounding holds for camera views and events never seen in training.

03 Video → Code World

Video to Code World via a Closed-Loop Agentic Pipeline

A training-free, closed-loop LLM agent, inspired by SpatialClaw, operates in a stateful Python kernel: it calls off-the-shelf perception models, inspects the intermediate results, and revises the world until it agrees with the video, without ground-truth labels or poses.

(a) Perception

Off-the-shelf tools, called on demand

(b) Closed-loop agent tool call

Render, compare, revise

After every edit, the agent renders the world onto the image and a bird's-eye view, compares it with the video, and revises it.

(c) Output

Editable Python scene file

  • Static world: buildings, walls, vegetation, lanes, poles, signs, traffic lights
  • Dynamic instances: persistent ID, fixed size, trajectory
  • scene_world.py, re-rendered within 10 cm and 7°

04 Instance-Level KV Memory

Long-Horizon Video Generation with Instance-Level KV Memory

An instance-level KV memory caches each object's tokens and re-embeds them where its block reappears. It uses about 24× less KV memory (GiB) than frame-level caching, and re-identifies 45.6% of returning vehicles, against at most 11.0% for prior methods.

(a) Cache

Per-instance KV storage

Keys and values are stored from each instance's most visible observations, together with box-local 3D coordinates.

(b) Re-embed

Re-embedding on return

When the instance reappears, its cached keys are re-embedded with rotary position where its block projects in the new frame.

(c) Attend

Instance-aware attention

An instance-aware attention mask lets each query read only the memory of the instance that owns it.

Long-Horizon Driving Video Generation with Instance Consistency

Minute-long generations. In the U-turn scenes the ego vehicle turns around and drives back along the same street, so buildings and parked cars are seen again from the other side; the straight scenes continue for about a minute. All methods start from the same real first frame.

Instance-Level Memory for General Video

The instance-level KV memory is not specific to driving or to one video model. Added to Wan2.1-VACE, a general-purpose controllable video model, it keeps people and faces consistent: an instance that leaves the view or turns away at a chunk boundary returns with the same identity.
