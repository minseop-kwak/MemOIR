Abstract

Video generative models promise driving simulators that can render arbitrary traffic scenarios, but this requires both precise control over the scene and consistency across long rollouts. Existing driving generators condition only on traffic participants and road layout, leaving the static world, and with it the ego motion, underspecified, while frame-level memories grow quickly and cannot tell which cached tokens belong to which instance. We present MemOIR, a driving video diffusion model conditioned on a view-space blocks-world representation that renders every dynamic and static instance as a 3D block encoding its class, identity, and occlusion, curated automatically from raw driving videos. This representation densely specifies both agent motion and the ego trajectory, and enables object-level KV caching: each instance's tokens are cached from its most complete observations and re-embedded where its block projects when it reappears, attending to far fewer tokens than frame-level caching. MemOIR achieves the most accurate instance placement and ego-motion control among driving generators with competitive visual quality, faithfully places vehicles performing unseen maneuvers such as spin-outs, and substantially improves the identity consistency of returning vehicles.

Part 1

Real → Sim: From Driving Video to a Code Blocks World

SceneClaw turns a raw dashcam video into a complete 4D blocks world. It is a closed-loop LLM agent that works in a stateful Python kernel and uses only off-the-shelf models and code: nothing it relies on is trained by us, and it uses no ground-truth labels or poses at inference.

Perceive

  • Depth Anything 3 (multi-view): metric depth and camera poses estimated from the video
  • Mask2Former panoptic segmentation and Mapillary Vistas lane markings
  • SAM3 text-prompted video tracking of vehicles, people, traffic lights, signs, poles, buildings and walls
  • WildDet3D 3D vehicle detection, with depth within 3–6% of ground truth out to 70 m
  • RTMPose pedestrian skeletons aligned to their boxes

Check and fix

  • The agent compares its world against image overlays and a bird's-eye view at several scales, including far-range sky and road checks, and repairs what does not match.
  • A final overlay check on the first, an intermediate and the last frame closes the loop.

Output: one program

  • Static world in the world frame: one aligned slab per building with street-side facade strips, walls, vegetation crowns, lane and road lines, poles, signs, and traffic lights with symbolic content.
  • Agents, each with one id, one size and a trajectory, plus per-frame traffic-light states.
  • Every run ends as a single editable Python file, scene_world.py, rendered by one universal renderer. The round trip stays within 10 cm / 7° and 0.6% of pixels.

Results

Each video shows the input camera, the reconstructed blocks world, and bird's-eye views at near and far range. Waymo Open and Argoverse 2 clips.

Part 2

Manipulate: Editing the Code World

Because every scene is a program, a new scenario is a few lines of code. Each agent is a route with a timing table, and a chainable scenario API changes when and how it moves. Static elements (buildings, trees, lines, traffic lights) are plain lists that can be edited directly. The edited world renders through the same renderer and becomes the condition for Part 3.

scene_world.py · illustrative edit 
# every agent: a route (xyz polyline) and timing {frame: metres along the route}
car = scene.car("veh017", kind, size, route=[...], timing={...})

car.set_speed(8.0, from_t=40)                  # slow down from frame 40
car.stop(at_t=60, decel=3.0)                  # brake to a stop
car.delay(15)                                 # arrive 15 frames later
car.lane_change(3.5, t0=50, t1=80)            # move one lane to the left
car.place(t, x, y); car.reroute([...]); car.span(t0, t1)

scene.clone("veh017", "veh900").delay(30)      # add a follower
scene.remove("ped045")                         # clear a pedestrian

Part 3

Sim → Real: Long-Horizon Generation with Object-Level Memory

A ControlNet-style control branch on a frozen Cosmos-Predict2.5-2B renders the blocks world back into real video. Videos are generated chunk by chunk, each chunk re-anchored on the last frame of the previous one. To keep instances consistent across chunks and after they leave the view, MemOIR keeps an instance-level KV bank.

Cache per instance

For each instance, keys and values are stored from its most visible observations, together with box-local 3D coordinates.

Re-embed on return

When the instance reappears, its cached keys are re-embedded with rotary position at the location where its block projects in the new frame.

Attend to your own

An instance-aware attention mask lets each query read only the memory of the instance that owns it.

Minute-Long Generation
